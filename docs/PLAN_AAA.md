## 0. Диагноз (замеры, а не ощущения)

**Анимации** — `tools/anim_audit.tscn -- 5 40` (скорость «запиненной» стопы, должно быть ≈0):

| категория | скольжение | доля > 0.5 м/с |
|---|---|---|
| бег вперёд / спринт | 0.13 / 0.00 м/с | 3% / 0% — нормально |
| шаг / трусца вперёд | 0.38 / 0.59 | 17% |
| трусца с поворотом | 1.64 | 41% |
| бег боком с поворотом | 6.05 | 80% |
| пас | 5.26 | 73% |
| удар | 10.0 | 100% |
| подкат / финт / подъём | 3.3 / 4.6 / 5.5 | 78–100% |
| **итого** | **1.47 м/с** | **25%** |

Вывод: прямой бег уже хороший; **ломаются повороты и все действия** — именно то, что видно в каждом эпизоде.

Причины в коде:
1. **Мяч не касается ноги.** Ближний контроль — мяч на «пружине» перед игроком (`match_sim.gd` `_dribble`, `corr * 10.0`). Касания в беговом дриблинге привязаны к фазе шага симуляции `o.gait`, а анимация крутится своим темпом (`ts/scale`) и с `gait` не синхронизирована.
2. **Удары выровнены только по времени** (пропуск разбега, `"contact"` в `character_view.gd sync`), но не по месту: нога в момент удара может быть в 20–40 см от мяча. На header/skill/celebrate IK выключен целиком. **Все действия только правой ногой.**
3. **Поворот = вращение манекена**: `_yaw = lerp_angle(..., dt*16)` — игрок крутится юлой, без шагов, разворотов и торможения.
4. **13 клипов набиты руками** (нырки вратаря, подкат, отбор, приём грудью, вброс, финты, падение) — выглядят «роботом».
5. **Разные актёры**: шаг ACCAD, бег CMU 102, стрейф 100STYLE, назад ACCAD → разная манера внутри одного игрока.
6. **Руки без IK**: мяч у вратаря = `gk.pos + face*0.3 + (0,1.05,0)` (`match_sim.gd:387`), руки его не держат. Вброс — то же.
7. Переходы — линейный кроссфейд («плывущие» смены поз), нет стартов/остановок, нет реакций на контакт.

**Графика** (после прохода 2026-11-20: небо, газон, Forward+/ULTRA, SSS):
- Игроки-варианты: **11k треугольников, кожа 1536 px, форма 512 px**, волосы 1k; лицевой анимации нет (0 морфов у вариантов).
- Толпа — плоские спрайты (8 вариантов × 2 позы).
- Стадион — коробки; нет скамеек, людей у поля, LED-бортов, экранов.
- Нет запечённого света (LightmapGI), нет «звезды» из 4 теней от мачт ночью.
- Нет ТВ-пакета: заставки, повторы с нескольких камер, карточки игроков.

## 1. Принципы

1. **Симуляция главная, вид подстраивается.** Ничего не меняем в геймплее ради картинки. Вместо этого:
   *motion warping* (подводим корень игрока к нужной точке), *IK* (ставим стопу/руки точно), *ball warping* (визуальное смещение мяча ≤ 15 см только в отрисовке).
2. **Каждый пункт — с метрикой и автотестом**, а не «вроде лучше». Метрики в §5.
3. **Мобильные — первый класс.** Всё дорогое — по уровням качества (§4). На телефоне IK/детали только у ближних игроков.
4. **Только легальные ассеты**: CC0 / CC-BY / Mixamo (бесплатно для игр). Без EA/FIFA/реальных клубов и игроков. Скриншоты FC/eFootball — только как внутренний референс, в игру не попадают.
5. **Нативный код для горячего пути.** В Godot 4.7 уже есть `TwoBoneIK3D`, `FABRIK3D`, `CCDIK3D`, `JacobianIK3D`, `AimModifier3D`, `LookAtModifier3D`, `SpringBoneSimulator3D`, `PhysicalBoneSimulator3D`, `LimitAngularVelocityModifier3D`, `AnimationNodeExtension`, `CompositorEffect` (проверено `ClassDB`). GDScript оставляем только для логики решений.

## 2. Анимации

### A1. Контакт ноги с мячом — самое заметное  `[x]` 2026-11-21  размер L
> Сделано: фаза шага вида привязана к `Footballer.gait` (общая таблица частот `Footballer.GAIT_TABLE`, коррекция темпа ±30%,
> скачок через `AnimationNodeTimeSeek` при ошибке > 0.3 цикла); касания планируются в симуляции (`touch_at/touch_foot`,
> окна фаз 0.86/0.36, упреждение ≥ 0.12 с), ближний контроль — касание каждый шаг вместо «пружины»; `FootPlanter.reach_*`
> тянет стопу к мячу, при нехватке длины ноги корпус наклоняется (`_reach_shift`, ≤ 0.2 м); приём мяча — ближняя нога навстречу.
> `tools/contact_audit.tscn`: касания |зазор| p90 **1.1–3.4 см**, удары **3.2 см**, приёмы p50 5.5 / p90 14 см (половина приёмов
> без выноса ноги: высокие/боковые мячи). Статистика матчей в норме (bench 5v5/11v11).
- [ ] **Фазовая синхронизация**: фаза локомоции в виде = `o.gait` из симуляции (blend-space клипы нормализованы на 1 цикл → ставим позицию клипа по фазе, cadence только сглаживает). Тогда «правая нога впереди» в симуляции = правая нога впереди на экране.
- [ ] **Планирование касаний в симуляции**: вместо пружины — реальные мягкие касания каждые 2–3 шага (ближний контроль) и толчки (беговой дриблинг); сим заранее (0.2–0.3 с) публикует `next_touch {t, foot, pos, type: inside/outside/sole/laces}`. Геймплей (скорость/контроль) сохраняем: тюним силу касаний под те же траектории, проверяем `bench`/`carrier_audit`.
- [ ] **TouchIK**: за 0.15 с до касания стопа (точка удара по типу касания) тянется к мячу через `TwoBoneIK3D` с кривой веса 0→1→0, ориентация стопы по типу касания.
- [ ] **Ball warping**: остаток ошибки (≤ 15 см) забирает визуальный офсет мяча, затухающий за 0.1 с после касания.
- [ ] Приём мяча (`TRAP`): нога/бедро/грудь выбираются по высоте мяча, стопа «гасит» мяч (IK + короткий клип).
- **Готово, когда**: ошибка «нога–мяч» в момент касания p90 < 4 см у ближних игроков (`contact_audit`, §5); на видео мяч не «плавает» рядом с ногой.

### A2. Удары, пасы, отборы — warping + IK + левая нога  `[~]` 2026-11-21  размер M
> Сделано: сим выбирает ногу (`strong_foot()`, слабая нога +25% к ошибке), зеркальные клипы `*_m` + беговой удар Mixamo
> `kick_run(_m)` для ударов на скорости, IK бьющей стопы в мяч и сдвиг корпуса (≤ 0.45 м) в замахе.
> Замах удлинён до ≥ 0.12 с (пас 0.12–0.18, удар 0.16–0.26), во время действий стопы всегда пинятся (`force_pin`).
> Удары: |зазор| p90 3.2–4.3 см. Осталось: в замахе опорная нога переставляется быстрым подшагом (аудит считает его
> скольжением, act_pass_pre ~7 м/с) → A3 (клипы с root motion / предвосхищение), `AimModifier3D` на корпус.
- [ ] **Motion warping** на подходе: за время до контакта корень плавно смещается/доворачивается так, чтобы опорная нога встала в ≈25 см сбоку от мяча, а бьющая попала в мяч в кадр `contact` (метаданные клипа: кадр контакта, нога, позиция мяча относительно корня в контакте).
- [ ] Финальные 10 см — IK бьющей стопы в мяч; опорная стопа **запинена** весь удар (IK не выключается на действиях).
- [ ] **Зеркалирование всех действий** (карта костей l↔r + отражение по X при импорте) → сим выбирает ногу по положению мяча (`act_data.foot`), у игроков появляется «сильная нога».
- [ ] Замах корпусом: `AimModifier3D` на spine_02/03 разворачивает грудь в направлении паса/удара за 0.2 с до контакта.
- [ ] Отбор/подкат: нога IK к мячу или к ноге соперника; при фоле — контакт ног соперников.
- **Готово, когда**: в `anim_audit` скольжение `act_pass/shot/lob/slide/skill` < 0.5 м/с; левые удары есть в матче (~30% у правшей при неудобном мяче).

### A3. Повороты и локомоция — убрать «юлу»  `[ ]`  размер L
> 2026-11-21: дерево анимаций переделано — `main` = переход «бег | слот 0 | слот 1», цепочки действий сменяются

| пост | tonemap | + glow | + DOF повторы | + motion blur, объёмный свет |

Цель: 60 fps на Medium для Adreno 6xx, 30 fps на Low для слабых Mali. Размер AAB: база ≤ 150 МБ, тяжёлые текстуры — Play Asset Delivery.

## 5. Проверка: «Temu-тест»

- **Метрики (автоматически)**: `anim_audit` (скольжение), новый `contact_audit` (ошибка нога–мяч в касании), `turn_audit` (скольжение на поворотах + пиковая угловая скорость корпуса), `fps_probe` на устройстве.
- **Фиксированные сцены** на каждой вехе: плечевая камера в дриблинге, ТВ-общий план, крупный план удара в повторе, празднование, нырок вратаря → контактные листы рядом с референсами.
- **Слепое ревью видео** через Gemini (`agy --model gemini-3.8-flash-high`) с чек-листом: скольжение ног, мяч без касания, вращение юлой, роботизированные нырки, пластиковая кожа, плоская толпа, пустой стадион. Цель — ноль замечаний из чек-листа.
- Игровая проверка: `bench` / `carrier_audit` до и после A1 — статистика матча не должна уехать.

## 7. Решения за пользователем / риски

- **Mixamo**: нужен один вход в Adobe-аккаунт → без него A4 пойдёт медленнее (CMU + видео→mocap).
- **Видео→mocap**: если нужны особые движения, понадобятся съёмки на телефон (ты/друзья, 1–2 вечера).
- Размер APK/AAB растёт от 4k-текстур → ASTC + Play Asset Delivery.
- Персонажей недавно параллельно правил OpenCode — перед работой в `blender/chars` проверять `pgrep -af opencode`, чтобы не было двух писателей.
